## Bundled assets (UI-22)

### Device SVGs

All 57 files in `web/assets/icons/svg/` and their `_icon-paths.json` table now
contain original in-house geometric paths generated by
[`tools/generate_clean_device_icons.py`](tools/generate_clean_device_icons.py)
under MPL-2.0. Filenames are preserved. Each SVG is below 5,120 bytes.
The full inventory and historical context are in
[`web/assets/icons/PROVENANCE.md`](web/assets/icons/PROVENANCE.md).

The previous files were potrace traces of PNG sprites, made by the retired
`scripts/convert-icons-to-svg.js`. The source sprites' license could not be
established; those traced vectors have been replaced, rather than assigned a
license without evidence. No source PNG sprites are bundled here.

`IconLibrary.getIconHtml()` in `web/js/utils/icon-library.js` renders the
existing inline 24x24 icons. External SVG rendering remains disabled in that
primary path, so replacing the unused external set does not alter those icons.

### Project assets and fonts

- `web/assets/favicon.svg` and
  `custom_components/hdmi_matrix/brand/icon.png` /
  `custom_components/hdmi_matrix/brand/icon@2x.png` are project artwork distributed
  under MPL-2.0. The brand PNGs are renders of the repository favicon.
- The inline vector primitives in `web/js/utils/icon-library.js` are project
  source under MPL-2.0. Device and product names identify compatible equipment.
- Bundled font binaries: **none**. The web UI uses system font stacks; no font
  files or external font stylesheets are shipped by this repository.

To refresh after a lock update, use the verified locked environment:

```sh
python -m pip install --require-hashes -r requirements.txt
python tools/update_third_party_licenses.py
```

The updater refuses version mismatches or distributions without supplied license
files. Review the notices and license inventory when dependency versions change.
The original license files also remain installed in the runtime distributions'
`.dist-info` directories; the hub does not replace or statically relink them.

## Development tools and external runtime resources

Python development tools in `requirements-dev.txt` and Node tools in
`package-lock.json` are used for builds, tests, linting, screenshots, and license
inventory generation; their packages retain their own installed license files.
They are not copied into the production Docker image. The browser documentation
page's external Swagger UI resources, if enabled, are supplied by the CDN under
the Swagger UI project's Apache-2.0 license; the page pins their version and
documents its network requirement.

## Vendor material and protocol evidence (SEC-14)

Vendor firmware, flashing utilities such as `XP3.exe`, proprietary `.c4z` driver
packages, and HAR captures are excluded from new commits by the repository
hygiene guard. Vendor manuals and binaries are not redistributed as project
assets; see [the vendor reference index](docs/vendor/README.md).

The [OREI protocol reference](docs/OREI_API_COMMANDS.md) distinguishes captured
wire behavior from implementation-derived commands and unobserved physical
effects. Simulator success does not establish a real display's CEC behavior or
replace the hardware release gates.
