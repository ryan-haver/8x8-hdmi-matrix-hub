# Current coordinator handoff template

Template only. Instantiate with observed receiving-repository facts, not values
from the kit's source project. Keep the current state first and old snapshots
explicitly historical.

## Current objective and authority

Record the user's authorized work, phase/wave, current status, repo root and
integration branch/remote, actual local/tracking/live remote heads, working-tree
changes and ownership. Record the existing Run/coordinator/runtime evidence and
protected resources. Do not claim an unobserved binding or clean working tree.

## Current work and evidence

Record accepted/provisional phase decision and packet hash, live task allocation,
author/reviewer identities, exact source heads, actual checks/findings, unsettled
Dispatches, pending questions and already completed resource decisions.

## Capacity and routing

Point to current catalog, dated quota/reset observations and cadence/checkpoints.
Record unknowns, shared commitments, review reserve, accepted fallback pairs,
actual handovers and original authorship. State whether a monitor is actually
running and its owner; policy text alone is not a persistent service.

## Preservation and publication

Record archives/bundle hashes, available transcript limits, task-branch remote
verification, managed cleanup state, exact completed-local-branch disposition,
integration publication evidence and work still required for wave closeout.

## Readiness and next action

Record actual target-specific gates and blockers; keep incomplete work pending.
Name the next authorized action and any exact missing prerequisite. Identify
closed-wave setup/cleanup scripts that must not be rerun. No proposed future
worker reservation is an actual Task or source grant.
