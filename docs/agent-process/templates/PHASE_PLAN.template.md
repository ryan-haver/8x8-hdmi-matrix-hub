# Phase preparation template

Template only. Create a phase-specific plan and populate actual evidence. Empty
sections are uninitialized, not decisions or approval.

## Purpose and baseline

- Phase/cycle, current user-authorized objective and program-direction reference.
- Exact current integration/dependency heads and latest applicable baseline.
- User outcome, implementation boundaries, non-goals and target architecture.
- Prerequisites, admitted environments, protected/shared paths and release gates.
- Dependencies, parallel-ready tracks, first useful result and wave sequence.
- Timeline range and explicit effort/capacity/review/environment assumptions.

## Acceptance and completion

Define observable behavior, real acceptance commands, consequential failure cases,
independent-review requirements, applicable combined checks and phase exit gates.
Separate actual executions from expectations and production qualification.

## Task and model assessment

| Task and worktree reservation | Scope, dependencies and exact base | Selected route and supported effort | Evidence and alternatives | Independent reviewer and family | Acceptance and fallback pair |
|---|---|---|---|---|---|

Populate one row per task/worktree. Explain language/component, task difficulty,
failure consequences, context/tool/platform needs and demonstrated competence.
Reservations do not establish live Task/Dispatch IDs. Final execution rows belong
in the wave record with observed requested/effective model and turn evidence.

## Capacity and handovers

Record applicable provider pools, observations and provider-update times, reset
windows, shared commitments, expected demand and review/correction reserve.
Define monitoring cadence/checkpoints, accepted author/reviewer fallback pairs,
bounded unknown-quota behavior, actual refusal handling, checkpoint artifacts,
ownership-transfer evidence and material-change criteria. Preserve independence
across all material authors; do not assume live-model swapping or background jobs.

## Three-round planning evidence

1. Record the common input manifest/hash, actual three-family participants and
   independent Round-1 reports. Keep peer reports unavailable until R1 settles.
2. Deliver all peer reports, preserve source-backed challenges and dispositions,
   then freeze a final plan/allocation and packet manifest/hash.
3. Record explicit final decisions on the same packet hash and unresolved dissent.

Keep full contribution/transcript provenance, exact effective models, exclusions
and provisional/missing coverage. Planning consensus is distinct from source
qualification and technical release. Fill the consensus record with actual data.

## Revalidation and closeout

For each wave, record whether assumptions, routes, competence, capacity and review
remain valid, and the exact current base. Use accepted fallback rules; material
unplanned changes require a fresh cycle for affected work. Close each wave through
actual review/integration/checks, settlement, preservation, managed cleanup and
verified publication before the next wave.

## Actual decision

Not started. Replace this with actual decisions and evidence references when
available. Do not declare consensus, qualification or phase release from the template.
