# Orca phase development

For adoption into another repository, read [README.md](README.md) and
[ADOPTION_PROMPT.md](ADOPTION_PROMPT.md), then reconcile the receiving repository's
instructions and bindings. Adoption creates process documents; it does not start
a phase, install software, change accounts or grant deployment authority.

For an authorized phase, read [PROTOCOL.md](PROTOCOL.md), the receiving repository's
filled `REPO_CONFIG.json`, live handoff and relevant phase/wave records. Load the
installed, version-matched Orca guides before any Orca operation, following
[ORCA.md](ORCA.md). Never substitute another agent framework for requested Orca
Task/Dispatch authority.

Evaluate actual task/model/worktree matches during every phase's three-round
debate. Monitor capacity while coordinating active work, use accepted fallbacks,
and preserve single-writer ownership and review independence during handovers.
Different routers or variants do not create independent model families.

Use only the relevant [templates](templates/) as starting shapes. Nulls and empty
arrays are uninitialized evidence, never completed debates, qualifications, quota
checks or release gates. Actual outcomes and current user instructions govern.

This optional skill entry point is portable. It contains no receiving repository
Run ID, branch, qualification history or production acceptance. Discover those
facts locally; do not import them from the repository that supplied the kit.
