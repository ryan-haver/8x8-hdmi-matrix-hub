# UI round 2: UI-55, UI-56, UI-57, UI-58

Branch `fix-ui-round-2`. Code `230d450`, approved baselines `b3aced1`.

## Owner decisions (2026-10-09, DI-15)

- **UI-57.** The owner first chose "show each widget once" (merge a widget card into the pinned
  widget). After the two dashboard systems were explained (pins saved per browser; the hub layout
  shared by all browsers; the card picker cannot add widget cards), the owner chose instead to
  **drop widget cards**. Routing and CEC Remote live only as pinned widgets, and the dashboard
  layout holds items only. This folds in UI-55: the retired Quick Actions card goes with the others.
- **First visit.** With widget cards gone, a new browser would show no CEC Remote. The owner
  chose to pin every widget registered on a browser's first visit. Saved pins are untouched.

## What changed

| Finding | Change |
| --- | --- |
| UI-55, UI-57 | `src/dashboard_layout.py` retires the `aggregate_widget` card type. A new install starts with an empty layout. A stored layout drops its widget cards once on load, renumbers the rest and saves. POST refuses widget cards (400) and PUT drops them. The web UI loses the widget-card renderer and its UI-44 hooks. |
| UI-57 | `dashboard-manager.js` decides "first visit" once per page load. Before, the CEC tray registered about 100 ms after the first widget had saved the config, so it was never auto-pinned. |
| UI-56 | The Settings drawer close button is a `btn-icon`, like the other drawers' close buttons. |
| UI-58 | `.modal` is laid out below the fixed header, and above the bottom tab bar on phones, using the main content's `--header-height` / `--tabs-height` pattern. `.modal-content` is at most that space and scrolls inside. Layering is unchanged, so toasts (z-index 300) stay above dialogs. |

New finding **UI-59** (low): the CSS does not follow the z-index scale in `LOOK_AND_FEEL.md`.
