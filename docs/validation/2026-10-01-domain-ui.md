# Direct macro and shortcut browser validation

This batch continues the coverage work in the [WP-C4 handoff](2026-09-30-wp-c4.md)
on `wp-domain-ui-validation`, branched from `wp-c4-scenes`. It adds validation
flows and evidence; it changes no application code or approved visual baseline.

## Scope

`macro_run` uses the Dashboard tab. If the macro has no card, Chromium opens
the card picker, selects the Macros tab, adds the card and dismisses the setup
toast. It then clicks Run. The happy case requires exactly three volume-up
frames to output 2 and a success toast. The refusal case requires exactly one
attempt, unchanged device state, an error toast and no success toast.

`shortcut_run` opens the Control Deck's Shortcuts drawer and clicks Execute.
The one-to-one flow uses the UI's `builtin.one_to_one` alias for the legacy
REST key `route_one_to_one`. REST parameter overrides remain available to the
API client; the browser client rejects them as unsupported before opening a
page, because the drawer has no override inputs.

The browser now exercises one-to-one routing, matrix standby, mute/unmute of
all eight outputs, preset 3 recall and the 15-second LCD setting. Each checks
the actual simulator command log and device state where applicable, plus the
success toast. A refused mute verifies unchanged state and an error without
success feedback. Existing parameterized routing, unknown-shortcut, beep,
panel-lock and scene macro-policy API scenarios remain in the scoped run.

The macro editor still has the missing-trigger limitation noted in the visual
catalog. Its editing flow is outside this batch. These records do not prove
all shortcut variants, a reboot, physical CEC effects or hardware operation.
